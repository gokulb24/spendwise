# Family Expense Tracker — Android app (Flutter)

A native Flutter port of the web app, with the **same features** and the **same
Firebase backend** — so the web app and the Android app share one live family
book. Any member's entry appears on everyone's phone within a second.

Features: email/password login, create/join a family by invite code, live
cross-device sync, add/edit/delete expenses, per-member income, category budgets
+ total override, KPIs, category & member charts, month switcher, and a
one-tap **monthly PDF report** (shared via the Android share sheet). Works
offline (Firestore caches locally and syncs when back online).

---

## What you need installed (one-time)

The build machine needs the Android toolchain (this is the part that wasn't set
up yet):

1. **Flutter SDK** — already downloaded to `~/flutter`. Add it to your PATH:
   ```bash
   export PATH="$HOME/flutter/bin:$PATH"
   ```
   (add that line to `~/.zshrc` to make it permanent)
2. **Android Studio** — <https://developer.android.com/studio>. On first launch
   it installs the **Android SDK**, **platform tools**, and a **JDK**. Then:
   ```bash
   flutter doctor --android-licenses   # accept all
   flutter doctor                      # should show Android toolchain ✓
   ```
3. A phone with **USB debugging** on, or an **emulator** created in Android
   Studio (Device Manager → Create device).

## Connect your Firebase project (one-time)

The app ships with a placeholder `lib/firebase_options.dart`. Point it at the
**same** Firebase project you used for the web app so both share data.

1. Install the CLIs:
   ```bash
   npm install -g firebase-tools
   dart pub global activate flutterfire_cli
   export PATH="$PATH":"$HOME/.pub-cache/bin"
   firebase login
   ```
2. From the `flutter_app` folder, run:
   ```bash
   flutterfire configure
   ```
   Pick your existing project. It regenerates `lib/firebase_options.dart` and
   creates `android/app/google-services.json` automatically.
3. Nothing else to change: **Email/Password** auth and the **Firestore security
   rules** were already enabled during the web setup (see `../SETUP-SYNC.md`).

> Haven't set up Firebase at all yet? Do the web guide first —
> `../SETUP-SYNC.md`, steps 1–4 — then run `flutterfire configure` here.

## Run it (development)

```bash
cd flutter_app
flutter pub get
flutter run          # pick your connected phone / emulator
```
On first launch: create an account → **Create family** (name + member names) →
you get an invite code. On another phone, install the app, sign up, and **Join
family** with that code. Add an expense on one phone; watch it appear on the other.

## Build an installable APK

```bash
flutter build apk --release
```
The file lands at:
```
build/app/outputs/flutter-apk/app-release.apk
```
Copy that to any Android phone and open it to install (allow "install from
unknown sources" once). Share it with family members the same way, or publish to
the Play Store with an app bundle:
```bash
flutter build appbundle --release   # build/app/outputs/bundle/release/app-release.aab
```

## Project layout

```
lib/
  main.dart              app entry + auth gate (loading → sign-in → family → home)
  firebase_options.dart  Firebase keys (regenerated by flutterfire configure)
  data/constants.dart    categories, payments, default budgets, palette, colors
  models/                Expense, Family
  state/app_model.dart   all Firebase auth + Firestore sync + app state (Provider)
  utils/                 formatting, month math, MonthSummary (pure), PDF report
  screens/               auth, family (create/join), home dashboard, account
  widgets/               KPIs, income, add-expense, charts, budget/member tables, log
test/                    unit tests (logic) + a full-dashboard render test
```

## Notes
- **Same data as the web app.** Both use `families/{id}` with an `expenses`
  subcollection and a `settings/config` doc — identical schema, so they interop.
- **Currency** is INR (₹). The PDF uses "Rs" because the built-in PDF font has no
  ₹ glyph.
- **Verified before shipping:** `flutter analyze` is clean, `flutter test` passes
  (logic + a dashboard render test using a fake Firestore), and `flutter build web`
  compiles the whole app. The APK build and on-device run require the Android
  toolchain above, which is the step to do on your machine.
